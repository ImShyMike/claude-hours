# time-track: handoff

A function-hooks mod (Claude Code plugin) that appends one JSON line per event
to `~/.claude/analytics/events/<sessionId>.jsonl`. It's loaded in every session through
`env.CLAUDE_CODE_PLUGIN_DIRS` in `~/.claude/settings.json`. Commits so far:
`2fcda39` (add), `ac7b07e` (cwd on every line + `cwd_changed`).

## What it logs

Each session file opens with a header, `{"v":1,"event":"session","start":<epoch ms>,"cwd":...}`. Every later row has `event` and `t` (ms since `start`; `at`, epoch ms, instead if a reload couldn't read the header back). No row repeats the session id (it's the file name) or the cwd: `cwd_changed` moves it, and `file` / `path` under it are relative. A field at its usual value is left out (`DEFAULTS` in `register.ts`: tool `outcome: ok`, turn_end `reason: answer`, file_changed `via: tool`, prompt `origin: composer` / `isMeta: false`, session_start `isInteractive: true`, compact `outcome: compacted`), and so is a typed draft's counter at 0. At `session.end` both of the session's files are appended to `<id>.jsonl.gz` as one more gzip member and the plain files removed. `config.json` beside them can `include` / `exclude` file paths by glob; a left-out path drops its `file_changed` row and the `file` on its `tool` row. Its `ignore` list (`/time-track ignore` toggles the cwd's repo root there) leaves whole folders out: no row is written while the cwd or its root is under one, and a path under one is left out like an excluded one.

| event | hook | extra fields |
|---|---|---|
| `session_start` | `session.start` (deduped across hot reloads via `$.state`) | `surface`, `isInteractive` |
| `session_end` | `session.end` | `reason` |
| `prompt` | `prompt.submit` (logged after `next`, so dropped prompts don't count) | `words`, `chars` (code points), `origin` (`composer` = typed), `command`, `isMeta`, `midTurn` (true when a main-loop turn was still running), `images` / `audio` / `documents` (how many of each were pasted or attached, never their names); for a typed draft also `composeMs`, `typingMs`, `edits`, `typedChars`, `pastedChars`, `deletedChars`, `fixes` (delete 3 chars or fewer, then retype), `rewrites` + `rewrittenChars` (more than 3, or typing over a selection), `pauses` (2 to 30 s gaps), `breaks` (over 30 s), `longestPauseMs`; the gap before Enter counts as a pause; a composer prompt that was only a paste has just `pastedChars` |
| (sidecar) `drafts/<sessionId>.jsonl` | written with each `prompt` / `draft_abandoned` that has a draft (same `draftId`) | `v: 1`, `outcome`, `startedAt` (epoch ms), `durationMs`, `initialShape` / `initialCursor` (left out when empty / 0), `steps`, `truncated` (only when true). Shapes only, run-length encoded: `a` a character, `_` a blank, `n` a newline (`5a_3a`). Steps are one string of `<dt><kind>[@pos][-removed][+shape][:who]` tokens (dt in 10ms ticks since the last step, rounded on the absolute clock, kinds t/p/r/b/d/w/k/m/c, a lone `a`/`_`/`n` is one char typed at the cursor; a missing pos is the cursor, a missing removed is 1 for b/d). Capped at 5000 steps / 50k shape chars |
| `draft_abandoned` | `prompt.edit` / `prompt.change` / `session.end` | the same draft fields, plus `how` (`clear`, `undo`, `deleted`, `exit`) and `endedAt` (epoch ms; it began `composeMs` before). Written late (at the next submit or at exit, never from a keystroke), so use `endedAt`, not `ts` |
| `turn_end` / `interrupt` | `turn.complete` (`reason: 'aborted'` → `interrupt`) | `turnId`, `agentId`, `reason`, `durationMs`, `usage`; a main-loop `interrupt` also has `answerChars` (answer shown so far, a count only) and `toolsRunning` (tool names still in flight, if any); a main-loop turn that had permission dialogs has `waits`, one `[ms before the turn's end it opened, ms open, tool]` each: it opens when `tool.check` answers `ask`, and how long is the turn's clock time minus `durationMs` (which leaves dialogs and questions out) minus its question calls, shared by how long each asked call ran |
| `compact` | `session.compact`, once it finishes; where a security plugin skips that, the transcript's `compact_boundary` entries, found at the next prompt, turn end or session end and stamped when the compaction finished (main thread only) | `trigger` (manual/auto/plugin/precompute), `agentId`, `messages` (count going in), `outcome` (compacted/skipped/threw), `tokensBefore`, `tokensAfter`, `usage`, `durationMs`; from the transcript only `trigger`, `tokensBefore`, `tokensAfter`, `durationMs` and the boundary's `uuid` |
| `tool` | `tool.call`, once it ends (a call that never ends leaves no row) | `tool`, `agentId`, `file` (built-in file tools only) / `commandChars`, `repo` (the git root it worked in when not the cwd's: a file's, or where a Bash command `cd`s first; a worktree's is its main repo; never the command), `repoName` (its origin remote's name, when not the folder's), `outcome`, `durationMs` |
| `file_changed` | `tool.call` | `path`, `via: tool` (Edit/Write/NotebookEdit) or `via: bash-window` |
| `mode` | `classic.UserPromptSubmit` / `classic.PostToolUse` / `classic.Stop`, main loop only, when the permission mode differs from the last one logged. Where a plugin above this one sends those events past it (the built-in `cc-plugin-sec-default` did on 2026-10-23), the transcript's prompts instead, each saying which mode it was sent in, stamped with the prompt's time and found at the next prompt, turn end or session end; a change between prompts shows up only at the next one | `mode` (`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`) |
| `cwd_changed` | inside `logAll()` whenever the cwd differs from the last row's, and once after a reload | `cwd` (the new one), `root` (its repo's folder, when that's not the cwd itself; the header has it too), `rootName` (the repo's name from its origin remote, when that's not its folder's) |

Prompt text and file contents are never written.

## Known limits (by design, for now)

- Delete kinds are guessed from the span first, the key second: a multi-char delete reaching the line's start or end is a line kill (`k`), any other multi-char delete a word delete (`w`). So Ctrl+W on a line's first word reads as a line kill unless the key says `w`. Cursor moves (`m`) are in the timeline only and never touch the stats.
- Text already in the box when a draft starts (a put-back prompt, a recall, typing from before a hot reload) doesn't count as pasted. Prompts logged before 2026-10-20 ~04:45Z may show it as pasted.

- An Esc right after sending interrupts the turn and puts the prompt back in the box. Deleting it then logs a `draft_abandoned` with `typedChars: 0`, while the prompt line stays (it was sent).
- Drafts: `typingMs` sums gaps between edits up to 30 s (plus the pause before Enter). `pastedChars` is any keyless insert of 32+ chars, plus the chars inside each `<pasted_content id="…">` block of the sent text (a big paste never reaches `prompt.edit`: the box folds it into a placeholder and the sent text carries it in full between those tags, which aren't counted). A composer prompt that was only a paste has no draft, so it carries `pastedChars` and nothing else. Abandoned drafts only see the keyless-insert part. Prompts logged before 2026-10-21 counted the sent text's leftover beyond the edits instead, so they include the tags, and recalled history entries show up as pasted. A stash (Ctrl+S) looks like a clear and logs as abandoned, and a draft put back from a stash starts a new one. A hot reload forgets the draft in progress and any abandoned drafts not written yet. Remote Control and `claude -p` prompts carry no draft fields.

- `bash-window` file changes = files under the cwd with an mtime after the Bash call started. It can't tell miggy's own edits from Claude's, misses writes outside the cwd, and catches at most 50 paths per call. `~/.claude/{projects,state,analytics,plugins}` are filtered out as noise.
- The org plugin `cc-plugin-sec-default` sits above mods and skips their `classic.SessionStart` hooks, so there's no `startup`/`resume`/`clear` source on `session_start`. Other `classic.*` events may get skipped too, so prefer engine events.
- `/clear` gives `session_end` with `reason: clear`, then lines under a new `sessionId` with no `session_start`.
- `$.session.cwd()` follows a Bash `cd`, but the `cd` call's own `tool` row still lands under the old dir. A hot reload forgets the last cwd, so it writes a `cwd_changed` before its first row even if nothing moved.
- Saving the hooks module swaps it at the next turn, not mid-turn (seen live 2026-10-20): calls in the turn that saved it still run the old code.
- Uploads: after `/time-track login <hub>` (device flow; `status`, `stats`, `ignore`, `statusline`, `update`, `logout`), each main-loop turn sends the session's new rows on the hub's sync protocol v1, fire and forget, and at session start a sweep sends finished sessions not all in; the exit's own rows wait for that sweep. `sent/<id>.json` (`v: 2`) counts lines per stream, so a send reads at most 4000 lines / 256 KB from there. Pack moves the file to `.packing` before gzipping so a concurrent read sees fewer lines, never doubled ones. Not yet seen live on this protocol (the byte-offset one was, 2026-10-20). Each sync's outcome lands in `$.store` under `health` (`okAt`, `error`), which `status` reads with a count of finished sessions not all in. With `"statusLine": true` in the config (`/time-track statusline`), after a sync the mod pins today's time with `$.ui.status`, asking `/v1/stats` at most once a minute. Off by default.
- On the hub, a project is named after the `root` the header or `cwd_changed` sent (the cwd's own folder without one): the hub can't look for `.git` on someone else's disk. Rows logged before 2026-10-20 have no `root`, so a session started in a subfolder still shows as that subfolder there. `rootOf` takes a worktree's repo from its common git dir, so `repo` and `root` name the main repo, never `.claude/worktrees/<x>`.
- A single line over 256 KB never uploads: the read cut back to whole lines comes back empty, so that stream stops there silently (and the sweep then marks the session done). Draft timelines are capped well below that.
- This build has no MultiEdit tool. If a later one does, add it to `EDIT_TOOLS`.

## Dev loop

- `claude plugin validate ~/.claude/mods/time-track`
- `claude plugin test ~/.claude/mods/time-track` (tests in `hooks/register.test.ts`, mocks answer `$` calls with `{ value }`)
- type-check: once a session has loaded the mod, the engine lays types in `.claude-plugin/types/` and `tsc -p ~/.claude/mods/time-track` works. The API reference is `.claude-plugin/types/claude-code/index.d.ts` (grep it for event names)
- headless smoke run from a scratch dir: `claude -p "<prompt>" --allowedTools Bash` (the prompt goes BEFORE `--allowedTools`, which swallows the args after it), then `jq -c . ~/.claude/analytics/events.jsonl`
- helpers that take `$` must be top-level functions, or validate refuses the module
- `find` in Claude's Bash shell is `bfs`, so `-newermt` gets whole-second ISO (`2026-10-19T21:32:40Z`), never `@epoch`
- `~/.claude/analytics/` stays OFF the `~/.claude` git allowlist
